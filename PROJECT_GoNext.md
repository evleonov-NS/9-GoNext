# PROJECT.md

## GoNext — Дневник туриста

---

## 1. Общее описание проекта

**GoNext** — мобильное приложение для планирования будущих путешествий, хранения интересных мест, создания конкретных поездок и ведения личного дневника путешествий.

Приложение строится вокруг естественного сценария пользователя:

> **Куда хочу поехать → Что хочу посетить → Планирую поездку → Еду → Отмечаю посещённое → Сохраняю воспоминания**

Приложение должно помогать пользователю пройти путь:

> от идеи «когда-нибудь хочу туда поехать»  
> к списку интересных мест  
> к конкретной поездке с датами и маршрутом  
> к подсказке «куда дальше» во время поездки  
> к личному дневнику после её завершения.

Приложение:

- работает **полностью офлайн**
- запускается на **мобильном телефоне**
- хранит **все данные локально на устройстве пользователя**
- не требует регистрации
- не требует серверной части в MVP
- не зависит от облачных сервисов для основной работы
- должно быть простым и быстрым в ежедневном использовании

---

## 2. Основная идея продукта

GoNext — это не просто список сохранённых мест и не просто планировщик маршрутов.

Главная логика приложения:

```text
ХОЧУ
↓
ПЛАНИРУЮ
↓
ЕДУ
↓
ВСПОМИНАЮ
```

### 2.1 ХОЧУ

Пользователь сохраняет:

- куда он хочет когда-нибудь поехать
- что он хочет посетить
- отдельные достопримечательности
- природные места
- рестораны
- музеи
- районы
- прогулочные точки
- любые другие интересные места

На этом этапе даты поездки могут быть неизвестны.

Пример:

```text
Хочу поехать:
Стамбул

Что хочу посетить:
- Айя-София
- Дворец Топкапы
- Гранд-базар
- Галатская башня
- Балат
- Кадыкёй
```

---

### 2.2 ПЛАНИРУЮ

Когда пользователь решает ехать, идея поездки превращается в конкретную поездку.

Появляются:

- даты
- список мест
- порядок посещения
- заметки
- маршрут

---

### 2.3 ЕДУ

Во время активной поездки приложение должно в первую очередь отвечать на вопрос:

> **Куда дальше?**

Пользователь видит:

- текущее состояние поездки
- сколько мест уже посещено
- какое место следующее
- возможность быстро открыть карту или навигатор
- возможность отметить место как посещённое
- возможность добавить заметку и фотографии

---

### 2.4 ВСПОМИНАЮ

После завершения поездки её маршрут становится личным дневником.

Сохраняются:

- посещённые места
- даты посещения
- заметки
- фотографии
- порядок маршрута
- понравившиеся места

---

## 3. Цели приложения

- Хранить список направлений, куда пользователь хочет поехать
- Хранить список конкретных мест, которые пользователь хочет посетить
- Не требовать сразу создавать поездку и выбирать даты
- Позволять постепенно собирать будущую поездку
- Превращать идею путешествия в конкретную поездку
- Планировать маршрут поездки
- Быстро показывать пользователю следующее место
- Открывать место на карте или в навигаторе
- Отмечать факт посещения
- Добавлять заметки и фотографии
- После поездки сохранять её как личный дневник
- Работать полностью локально и без регистрации

- территория
- маршрутная идея

Примеры:

- Стамбул
- Алтай
- Карелия
- Прага
- Золотое кольцо

### Что хочу посетить

Конкретные места:

- музей
- достопримечательность
- ресторан
- природный объект
- район
- рынок
- смотровая площадка
- другое место

В разделе доступен поиск по названию направлений и мест (как в разделе «Места»).

## 7.2 Сущность TripIdea — идея поездки

Идея поездки не имеет обязательных дат.

### Поля

```text
id
title
description
coverPhoto
status
createdAt
updatedAt
```

### status идеи

Допустимые значения:

```text
active
converted
archived
```

- `active` — обычная идея, отображается в списке
- `converted` — из идеи уже создана поездка; по умолчанию скрывается или показывается отдельной группой
- `archived` — пользователь убрал идею в архив без удаления

Пример:

```text

Стамбул

```

## 7.5 Превращение идеи в поездку

При нажатии:

```text

```

пользователь указывает:

```text
Название поездки
Дата начала (необязательно)
Дата окончания (необязательно)
```

Даты можно указать позже — до момента старта поездки (см. 10.4).

После подтверждения создаётся `Trip`.

Все выбранные места копируются в `TripPlace`.

Важно:

- `Place` не дублируется
- исходная `TripIdea` сохраняется, её статус меняется на `converted`
- создаётся новая конкретная поездка
- порядок мест можно изменить после создания поездки
- приоритет мест (`priority`) копируется из `TripIdeaPlace` в `TripPlace`

# 8. Раздел «Места»

## 8.1 Назначение

`Place` — единая личная база конкретных мест пользователя.

Место существует независимо от конкретной поездки.

Одно и то же место может:

- быть просто сохранено
- находиться в списке «хочу посетить»
- входить в одну или несколько поездок
- быть посещено
- быть отмечено как понравившееся

---

## 8.2 Сущность Place

### Поля

```text
id
name
city
description
category
latitude
longitude
visitLater
liked
createdAt
updatedAt
```

### city

Текстовое необязательное поле: город / регион / направление.

Используется как подпись в списках:

```text
Гранд-базар
Стамбул · рынок

Водопад Кивач
Карелия · природа
```

Без этого поля общая база мест превращается в неразличимый список названий.

### Координаты

Для GPS-координат используются отдельные поля:

```text
latitude
longitude
```

в формате Decimal Degrees.

**Координаты необязательны.** Пользователь часто сохраняет место только по названию («Гранд-базар»), не зная координат.

Правила поведения:

- координаты есть → доступны «Открыть карту», «Навигатор», «Скопировать координаты»
- координат нет → «Открыть карту» выполняет поиск по названию места во внешнем картографическом приложении; кнопка «Скопировать координаты» не отображается
- координаты можно добавить к месту в любой момент

## 8.5 Фильтры

Минимальные фильтры:

```text
Все
Хочу посетить
Посещённые
Понравилось
```

Правила фильтров:

- «Хочу посетить» — `visitLater = true`
- «Понравилось» — `liked = true`
- «Посещённые» — вычисляется: место считается посещённым, если у него есть хотя бы одна запись `TripPlace` со статусом `visited` в любой поездке. Отдельный флаг в `Place` не хранится.

Дополнительно можно фильтровать по категории.

# 10. Раздел «Поездки»

## 10.1 Назначение

Поездка — это конкретное путешествие с датами и упорядоченным маршрутом.

В отличие от `TripIdea`, поездка является конкретным планом.

---

## 10.2 Сущность Trip

### Поля

```text
id
title
description
startDate
endDate
status
current
createdAt
updatedAt
```

`startDate` и `endDate` — **необязательны при создании** (статус `planned`). Поездку можно создать сразу, а даты указать позже. В списках поездка без дат подписывается «даты не указаны».

---

## 10.3 Статус поездки

Рекомендуемые значения:

```text
planned
active
completed
```

В интерфейсе:

```text
Будущая
Текущая
Завершённая
```

Поле `current` можно оставить в MVP для простоты, однако `status` должно считаться основным состоянием поездки.

Одновременно активной должна быть не более чем одна поездка.

---

## 10.4 Переходы статусов

Статус поездки меняется **только вручную**, автоматических переходов по датам нет.

```text
planned
↓ кнопка «Начать поездку»
active
↓ кнопка «Завершить поездку»
completed
```

Правила:

- Кнопка «Начать поездку» доступна в карточке поездки со статусом `planned`
- **Для старта поездки даты обязательны**: если у поездки не указаны `startDate`/`endDate`, кнопка «Начать поездку» сначала открывает форму дат
- Если наступила `startDate`, а поездка не начата — на Главной показывается баннер-подсказка: «Сегодня начинается Стамбул — начать поездку?» с кнопками «Начать» и «Позже» (скрывает баннер до следующего запуска)
- При старте новой поездки, если уже есть активная, — диалог: «„Карелия" ещё не завершена. Завершить её и начать „Выборг"?» с действием «Завершить и начать»
- Кнопка «Завершить поездку» доступна в карточке активной поездки; после отметки последнего непосещённого места приложение само предлагает завершить
- Завершённую поездку можно вернуть в `active` (пользователь ошибся) — через меню карточки

Автопереход по датам не используется намеренно: перенос дат поездки не должен неожиданно менять её состояние.

# 11. Сущность TripPlace

`TripPlace` — конкретное место внутри конкретной поездки.

Она хранит не само место, а его состояние в рамках поездки.

### Поля

```text
id
tripId
placeId
order
dayNumber
status
visitDate
liked
notes
priority
createdAt
updatedAt
```

---

## 11.1 Статус места в поездке

Поле `status` заменяет простой флаг `visited` и имеет значения:

```text
pending
visited
skipped
```

В интерфейсе:

```text
Не посещено
Посещено
Пропущено
```

`skipped` необходим для корректной работы режима «Следующее место»: если пользователь решил не посещать точку, она помечается пропущенной и логика переходит к следующей, а не застревает.

---

## 11.2 Привязка к дню поездки — dayNumber

`dayNumber` — необязательный номер дня поездки (1, 2, 3, …), к которому запланировано место.

Зачем нужен:

- карточка поездки может показывать маршрут, сгруппированный по дням
- дневник завершённой поездки строится по дням (см. раздел 15.1)
- «День N из M» на Главной вычисляется из дат поездки, а план на день — из `dayNumber`

Правила:

- поле может быть `null` — место без привязки к дню показывается в группе «Без дня»
- при изменении дат поездки значения `dayNumber`, превышающие новую длительность, сбрасываются в `null` с уведомлением пользователя

---

## 11.3 Отметка «понравилось» на уровне посещения — liked

`liked` в `TripPlace` — «понравилось в этой поездке». Используется в дневнике: у посещения показывается тег «♥ понравилось».

Отличие от `Place.liked`:

- `Place.liked` — общая отметка места в личной базе
- `TripPlace.liked` — впечатление от конкретного посещения

Правило синхронизации: при установке `liked = true` в посещении отметка также ставится в `Place.liked` (место автоматически попадает в фильтр «Понравилось»). Обратной синхронизации нет: снятие отметки с `Place` не меняет историю посещений.

---

## 11.4 Почему TripPlace необходим

Например, место:

```text
Гранд-базар
```

в `Place` хранит общую информацию.

Но в поездке:

```text
Стамбул 2026
```

для него появляются:

- порядок маршрута
- день поездки
- статус (не посещено / посещено / пропущено)
- дата посещения
- заметка
- фотографии
- приоритет

Поэтому эти данные принадлежат `TripPlace`, а не `Place`.

- удалять место из поездки
- открывать карточку места
- отмечать посещение
- помечать место пропущенным
- добавлять заметку
- добавлять фотографии
- начать / завершить поездку (см. 10.4)

---

## 12.1 Добавление мест из базы — экран выбора

Кнопка «+ Добавить место» в карточке поездки и в карточке идеи открывает единый экран выбора из базы «Места»:

- список мест с чекбоксами, множественный выбор
- места, уже добавленные в эту поездку/идею, в списке не показываются
- кнопка внизу: «Добавить N мест» (неактивна, пока ничего не выбрано)
- если подходящих мест нет — пустое состояние с кнопкой «Создать новое место»

Добавленные в поездку места получают `status = pending`, `dayNumber = null`, `priority = optional`.

---

## 12.2 Bottom sheet места в маршруте

По кнопке «⋯» у элемента маршрута открывается нижний лист с быстрыми действиями:

```text
Водопад Кивач
Природа · Карелия

День:      [Без дня] [День 1] [День 2] [День 3] [День 4]
Приоритет: [Обязательно] [Если успею] [Просто интересно]

[Посещено]
[Пропустить]
[Удалить из поездки]
```

Правила:

- чипы дней формируются из длительности поездки + «Без дня»
- «Удалить из поездки» — с подтверждением: «„Название" останется в общей базе «Места» — удалится только из маршрута этой поездки»
- назначение дня и приоритета применяется сразу, без кнопки «Сохранить»

# 13. Изменение порядка маршрута

Пользователь должен иметь возможность менять порядок `TripPlace`.

MVP:

- кнопка «вверх»
- кнопка «вниз»

**Правило перестановки и дней:** день привязан к позиции в маршруте, а не «едет» вместе с местом. При перестановке двух соседних мест их значения `dayNumber` меняются местами — место, вставшее на позицию, получает день этой позиции. Так порядок маршрута всегда остаётся согласованным с последовательностью дней. Явное переназначение дня — через bottom sheet места (12.2).

После стабилизации проекта можно заменить на drag & drop.

Для учебного MVP рекомендуется сначала реализовать надёжное изменение порядка кнопками.

# 14. Режим «Следующее место»

## 14.1 Назначение

Это одна из ключевых функций GoNext.

Во время активной поездки приложение должно быстро показать:

> **Куда идти или ехать дальше?**

---

## 14.2 Логика

1. Найти активную поездку
2. Получить `TripPlace`
3. Отсортировать по `order`
4. Найти первое:

```text
status = pending
```

5. Это место считается следующим

Места со статусом `visited` и `skipped` при поиске следующего места пропускаются.

Если мест со статусом `pending` не осталось — показать экран «Все места пройдены» с предложением завершить поездку.

---

## 14.3 Экран

Пример:

```text
Следующее место

Водопад Кивач

Природа

62.268...
33.981...

Заметка:
Парковка находится рядом со входом.

[Открыть карту]

[Навигатор]

[Скопировать координаты]

[Посещено]

[Пропустить]
```

Кнопка «Скопировать координаты» показывается только при наличии координат у места.

---

## 14.4 После отметки «Посещено»

Приложение:

1. устанавливает:

```text
status = visited
```

2. записывает `visitDate`
3. показывает **экран подтверждения посещения** (мини-форма, а не toast):

```text
✓ Посещено

Водопад Кивач
12 августа

[Поле заметки: «Как впечатления?»]

[+ Добавить фото]

[♡ Отметить «понравилось»]

[К следующему месту]
```

Правила мини-формы:

- заметка сохраняется в `TripPlace.notes` при переходе дальше (если поле не пустое)
- «понравилось» пишется в `TripPlace.liked` и синхронно в `Place.liked` (см. 11.3)
- фотографии привязываются к посещению (`tripPlaceId`)
- все поля необязательны — можно сразу нажать «К следующему месту»
- если непосещённых мест не осталось, кнопка меняется на «Все места пройдены» и ведёт на итоговый экран с предложением завершить поездку

4. рассчитывает следующее место

---

## 14.5 Пропуск места

Кнопка «Пропустить» на экране следующего места (и в маршруте поездки):

1. устанавливает `status = skipped`
2. рассчитывает следующее место

Пропущенное место:

- отображается в маршруте с пометкой «пропущено»
- не учитывается в счётчике «посещено N из M» как посещённое
- может быть возвращено в статус `pending` из маршрута (пользователь передумал)

---

## 14.6 Открытие карт, навигатора, копирование координат

Приложение работает офлайн и не содержит встроенной картографии. Вся навигация — через внешние приложения и буфер обмена.

### Скопировать координаты

Основной универсальный способ: координаты копируются в буфер обмена в формате

```text
62.267500, 33.980800
```

(широта, запятая, пробел, долгота — Decimal Degrees, 6 знаков после точки).

Этот формат вставляется в строку поиска любого навигатора: Яндекс Карты, Яндекс Навигатор, Google Maps, 2ГИС, Organic Maps, OsmAnd и др.

После копирования показывается toast: «Координаты скопированы».

### Открыть карту / Навигатор

Реализация через системные ссылки:

- Android: `geo:<lat>,<lng>?q=<lat>,<lng>(<название места>)`
- iOS: Apple Maps `http://maps.apple.com/?ll=<lat>,<lng>&q=<название>`
- при отсутствии координат: поиск по названию — `geo:0,0?q=<название места>` (Android) / `maps.apple.com/?q=<название>` (iOS)

ОС сама предложит установленное картографическое приложение. Отдельные интеграции с конкретными навигаторами в MVP не делаются — копирование координат покрывает все случаи.

# 22. Правила целостности данных

- `Place` является основной записью конкретного места
- одно место нельзя копировать при каждом добавлении в поездку
- `TripIdeaPlace` содержит состояние места внутри идеи
- `TripPlace` содержит состояние места внутри конкретной поездки
- удаление места должно учитывать существующие связи
- удаление поездки не должно автоматически удалять `Place`
- удаление `TripIdea` не должно автоматически удалять `Place`
- фотографии удаляются из файловой системы вместе с соответствующей записью, если пользователь подтверждает удаление
- порядок мест хранится числом `sort_order`; значения назначаются с шагом 10 (10, 20, 30, …) — перестановка двух соседних мест не требует пересчёта всей таблицы
- при создании и редактировании поездки: если указаны обе даты, проверяется `endDate >= startDate`; даты необязательны для статуса `planned`, но обязательны для перехода в `active`
- «День N из M» на Главной не хранится, а вычисляется из текущей даты и дат поездки
- `dayNumber` места не может превышать длительность поездки; при сокращении дат лишние значения сбрасываются в `null`
- одновременно не более одной поездки со статусом `active`

# 29. Архитектурный принцип

UI-компоненты не должны напрямую выполнять SQL-запросы.

Рекомендуемое разделение:

```text
UI
↓
hooks / services
↓
repositories
↓
SQLite
```

Например:

```text
PlaceScreen
↓
usePlaces()
↓
placeRepository
↓
SQLite
```

Это упростит учебную разработку, тестирование и дальнейшее развитие.

# 32. Основной принцип разработки в Cursor

Cursor должен реализовывать проект последовательно.

Не создавать весь проект одной большой генерацией.

Для каждого этапа:

1. прочитать `PROJECT.md`
2. определить текущую задачу
3. проверить существующую структуру
4. изменить только необходимые файлы
5. не ломать уже работающий функционал
6. не менять выбранный стек
7. не добавлять библиотеки без необходимости
8. после реализации проверить типы и ошибки
9. кратко описать, что изменено
10. указать, что делать следующим шагом

# 33. Главный продуктовый принцип

При любой доработке необходимо проверять:

> Делает ли эта функция путь пользователя проще?

Основной путь GoNext должен оставаться:

```text
Куда хочу поехать
↓
Что хочу посетить
↓
Создать поездку
↓
Построить порядок
↓
Следующее место
↓
Посетить
↓
Фото и заметка
↓
Дневник
```

Если новая функция не помогает этому сценарию, её не следует добавлять в MVP.

# 34. Итоговая концепция

GoNext — персональный офлайн-помощник путешественника.

Он объединяет три состояния одной и той же информации:

```text
МЕЧТА
«Когда-нибудь хочу туда»
```

```text
ПЛАН
«Я еду туда с 2 по 6 октября»
```

```text
ВОСПОМИНАНИЕ
«Я был там 4 октября, вот мои фото и заметки»
```

Одно сохранённое место постепенно проходит через весь жизненный цикл путешествия, не требуя от пользователя заново создавать одни и те же данные.
